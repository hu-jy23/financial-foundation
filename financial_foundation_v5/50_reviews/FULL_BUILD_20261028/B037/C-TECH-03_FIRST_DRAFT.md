# 云服务与超大规模云厂商

> 执笔：`/root/resume_b037`；2026-10-30制作。共同年度比较采用Amazon／Alphabet自然年2025及Microsoft截至2025-06-30财年；新增事件仅将Amazon延伸至2026-10-29，未把不同公司的观察日伪装成统一实时截面。

## 概念定义

云服务通过网络把可配置的计算、存储、软件和其他资源提供给客户，客户可以按需取得、扩展和释放资源。NIST定义强调自助服务、网络访问、资源池化、快速弹性及可计量使用。它改变的是资源交付与管理方式，不只是把服务器放在外部机房。[S-C-TECH-03-01](#S-C-TECH-03-01)

超大规模云厂商是拥有大规模数据中心、网络、软件调度和客户服务体系，能够持续扩展多类云资源的企业。本页以AWS、Microsoft Azure和Google Cloud为主要经营观察对象；“超大规模”是产业描述，不是统一会计分部或有固定服务器门槛的监管分类。大型互联网公司可能拥有同样庞大的内部计算设施，但若主要供自用，其资本开支不能直接计为对外云服务市场收入。

## 概念详解

### 客户购买的不只是服务器时间

| 服务层次 | 客户主要取得什么 | 主要经济含义 |
|---|---|---|
| 基础设施IaaS | 计算实例、存储与网络资源 | 客户仍管理大量软件，以资源量及时间计费较常见 |
| 平台PaaS | 托管数据库、开发与模型部署环境等 | 厂商承担更多运维，客户购买可用功能与管理便利 |
| 软件SaaS | 直接使用已运行的应用 | 常按账户、席位、订阅期或业务使用量收费 |

这些层次描述客户和提供者的控制分工，商业产品可组合多层。模型API可以把底层加速器、模型软件和运维包装成输入／输出token收费；客户不必持有GPU，却仍依赖厂商可用容量。NIST的分类提供基本边界，具体产品收入必须以企业披露核实。[S-C-TECH-03-01](#S-C-TECH-03-01)

云厂商把不同客户的需求放入资源池，减少每个客户独自按峰值建机房的需要，并通过自动化运维和规模采购摊薄成本。但资源不能无条件混用：地区、数据驻留、处理器类型、网络拓扑和可靠性要求会限制调度。全球剩余容量充足，某个地区的AI集群仍可能供不应求。云的“弹性”是客户侧的交付特征，不代表供给者能在瞬间建出新电力和机房。

### 收入如何从合同变成实际金额

消费计费随实际计算、存储或调用量确认，订阅计费通常随服务期确认。长约可以包含最低消费承诺、折扣、预付款或未来部署计划；签约、开票、收现和确认收入不是同一时点。Microsoft和Alphabet的会计政策都区分消费与订阅确认方式。[S-C-TECH-03-02](#S-C-TECH-03-02)、[S-C-TECH-03-04](#S-C-TECH-03-04)

**假设算例：** 客户签下三年最低消费900万美元的合同，假设按实际交付的服务确认收入，第一年实际履行240万美元，则不能在签约日或第一年将900万美元全部记作已交付收入。若第一年已预付300万美元，收现又高于已确认收入60万美元。其余部分怎样分配，要看具体履约义务及合同条款；该例只用于区分合同、现金和收入，不代替真实合同的会计判断。

剩余履约义务（RPO）是已签合同中尚待履行的收入承诺，常包括递延收入和未来才开票的金额。Alphabet截至2025年末披露2428亿美元RPO，主要涉及Google Cloud，预计略超过一半在未来24个月确认；该口径排除原预计期限一年及以内和可取消合同。因此，它既不是下一年收入，也不是全部潜在需求，更不等于已经收取的现金。[S-C-TECH-03-04](#S-C-TECH-03-04)

### 客户组合决定收入的稳定性与建设风险

企业迁移数据库、应用和数据分析平台，通常需要身份权限、网络、备份和长期运维配合；已有部署会形成切换成本。模型开发商则可能集中需求于大规模、连续、互联紧密的训练和推理容量。两类客户都能签长约，但需求波动、技术替换和融资依赖不同。同样一美元合同额，对地域、芯片和交付时点的要求不同，建设风险也不同。

客户还可能同时是合作伙伴、被投资企业或其他业务的供应商。Amazon 2025年报记录投资Anthropic可转换票据等活动；微软年报则披露与OpenAI的投资和商业联系。研究时应把投资现金流、云服务收入、应收款和合同承诺分别记录，判断服务是否交付及款项能否回收。存在双重关系不自动证明收入无效，也不能把融资流入当成终端需求已经独立盈利。[S-C-TECH-03-03](#S-C-TECH-03-03)、[S-C-TECH-03-02](#S-C-TECH-03-02)

## 收入和资本开支为什么容易比错

### 云收入的边界并不相同

以下金额均为**十亿美元**，保留报告名称与期间，不作同口径市场份额排名。

| 企业披露口径 | 期间 | 收入 | 营业利润或边界说明 |
|---|---|---:|---|
| AWS分部 | 自然年2025 | 128.725 | 营业利润45.606；包含多类云服务，不能视为全部AI收入 |
| Microsoft Azure | FY2025，截至6月30日 | 超过75 | 管理层首次在该次业绩沟通给出这一年度规模；未单独给出Azure营业利润 |
| Microsoft Cloud | 同上 | 168.9 | 包含Microsoft 365商业云、Azure及其他云、LinkedIn商业部分、Dynamics 365，范围远大于Azure |
| Google Cloud分部 | 自然年2025 | 58.705 | 营业利润13.910；包含GCP、Workspace及其他企业服务 |

依据：[S-C-TECH-03-02](#S-C-TECH-03-02)、[S-C-TECH-03-03](#S-C-TECH-03-03)、[S-C-TECH-03-04](#S-C-TECH-03-04)、[S-C-TECH-03-05](#S-C-TECH-03-05)。AWS营业利润率按两项相除约35.4%，Google Cloud约23.7%；服务组合和成本分配不同，差额不能直接解释为相同GPU的盈利能力差异。

“Azure及其他云服务增长率”“Intelligent Cloud分部收入”和“Microsoft Cloud收入”也不是同一指标。微软的Intelligent Cloud还包括其他服务器相关业务；不能用一个口径的增长率乘另一个口径的收入，倒推出未披露的AI收入。

### 资本开支有现金、资产和承诺三个时间表

建云平台通常先取得土地、电力和机房，再安装服务器与网络，最后在系统上线后产生客户收入。建筑和供电设施可以服务多代设备，服务器的更新节奏通常更快。因此，资本开支总量必须进一步分成长寿命基础设施和更新较快的设备，并记录何时开始服务。

| 资本投入观测 | 2025已核数值，十亿美元 | 解释 |
|---|---:|---|
| Amazon集团现金资本开支 | 128.3，2024年77.7 | 技术基础设施大部分支持AWS，但也含履约网络；不能全记为AWS或AI |
| Microsoft集团现金购建物业设备 | 64.551，上一财年44.477 | FY2025现金流量表项目；另有融资租赁取得资产 |
| Microsoft融资租赁新取得使用权资产 | 20.511 | FY2025非现金取得资产口径，不是当年支付同额租金 |
| Alphabet集团购置物业设备 | 91.447，2024年52.535 | 主要为技术基础设施，同时支持内部产品和对外服务 |

依据：[S-C-TECH-03-02](#S-C-TECH-03-02)、[S-C-TECH-03-03](#S-C-TECH-03-03)、[S-C-TECH-03-04](#S-C-TECH-03-04)。三家公司均非只经营云，不能拿集团投入直接除以云收入，称作统一口径的云资本开支率。

融资租赁尤其容易造成跨口径误读。微软在2025-07-30电话会上称该财季资本开支242亿美元，包括65亿美元融资租赁，现金支付物业设备为171亿美元；公司解释租赁开始时确认其全值，且该季超过一半投入为长期资产。242与171的差额主要由租赁解释，但两者并非简单只差65，其他时间及计量差异也应保留，不能强行配成一个等式。[S-C-TECH-03-05](#S-C-TECH-03-05)

折旧把已经投入使用的资产成本分摊至以后利润表；现金资本开支先影响现金流。提高折旧寿命会减少当期会计费用，却不自动增加现金，也不保证旧设备能长期保持竞争力。对尚未开工或尚未生效的长期租约，更应区分未来承诺、已经取得的资产和当期付款。

### 收入增长与自由现金流下降可以同时发生

按简化现金口径，集团自由现金流可写作经营现金流减去净现金资本开支。它不是云分部利润的替代指标：经营现金流还受集团其他业务、营运资金、税款和非现金调整影响，融资租赁也需要另看未来支付。

Amazon披露2025年经营现金流1395亿美元、自由现金流112亿美元，而2024年自由现金流382亿美元；公司将下降主要归因于净购建物业设备支出增加507亿美元。这个组合说明经营规模扩大可以伴随建设支出更快上升。不能据自由现金流下降单独判定云需求恶化，也不能据营业利润上升判定投资已完成回收。[S-C-TECH-03-06](#S-C-TECH-03-06)

## 观测与比较的方法

分析一季增长时，把实际消费、价格和合同结构分开。AWS 2025年报称收入增长主要来自客户使用增加，部分被长约带来的价格变化抵消；收入增长率因此不等于物理计算量增长率。[S-C-TECH-03-03](#S-C-TECH-03-03)外币换算也会改变报告增长，固定汇率增长只是剔除汇率后的比较，不是另一笔收入。

对投资兑现，应按“客户承诺—建设与设备交付—可用容量—实际使用—开票收款”的链条追踪。RPO增加可以提高未来收入可见性，但交付时点、客户实际使用和合同集中度决定兑现速度。集团总收入分散，也不能证明一个新增AI集群没有集中客户风险。

年化运行率是用近期速度外推一整年，与过去十二个月累计收入不同。季度收入乘四能够显示当前规模，却没有包含未来季节性、涨价、扩容或需求变化，不能标作全年已实现收入。

## 本对象的历史与预期

**2011年：服务模式有了共同语言。** NIST将云界定为按需访问共享资源池，并区分服务与部署模式。这使“有服务器托管”与“具备弹性、计量和自动化交付的云服务”可以分辨。后来的AI基础设施沿用了这种资源交付方式，但更大训练集群对连续容量和网络协同提出了额外要求。[S-C-TECH-03-01](#S-C-TECH-03-01)

**2024—2025：收入扩张与资本投入同时加速。** AWS年度收入从1075.56亿美元增至1287.25亿美元，Google Cloud从432.29亿增至587.05亿美元；对应两家集团资本投入增幅更大，见上表。微软截至2025年6月的财年Azure收入超过750亿美元，全年现金购建设备投入也由444.77亿美元升至645.51亿美元。这些年度数据展示建设周期，并不证明新增投入全部专供AI或当年已经上线。[S-C-TECH-03-02](#S-C-TECH-03-02)—[S-C-TECH-03-05](#S-C-TECH-03-05)

**2025年7月的专业预期。** 微软CFO Amy Hood当时预计FY2026上半年仍受容量约束，下一财季资本开支超过300亿美元；并表示大型融资租赁交付会使季度支出波动。这里的上半年属于微软财年，不能写成自然年2026年上半年；它解释了为什么管理层同时预期高需求和较高建设现金需求。本页未逐季核验这项预测后来是否完全实现。[S-C-TECH-03-05](#S-C-TECH-03-05)

**2026年2月的当时投资指引。** Alphabet在2月4日预计自然年2026资本开支1750亿—1850亿美元；Amazon在2月5日预计集团约2000亿美元，并表达长期资本回报的信心。两者均为当时管理层预测，覆盖集团不同业务，不能相加后称为纯云或纯AI资本开支；也不能当作已经支付的金额。[S-C-TECH-03-06](#S-C-TECH-03-06)、[S-C-TECH-03-07](#S-C-TECH-03-07)

**2026年10月29日新增观察：规模、利润与现金投资分化。** Amazon公布截至9月30日第三季AWS收入459.84亿美元、营业利润177.73亿美元；该季收入年化约1840亿美元，而过去十二个月实际AWS收入为1613.82亿美元。集团过去十二个月经营现金流1683亿美元，自由现金流为流出424亿美元；集团现金流口径不能被称作AWS单独现金流。Jassy当时预测AWS在2027和2028年收入增速均超过40%，这是管理层前瞻判断，尚无对应未来结果。[S-C-TECH-03-08](#S-C-TECH-03-08)

**本库条件推演，2026-10-30整理：** 如果新增容量按时上线、客户使用扩大且合同价格覆盖设备更新与运营成本，较早投入的固定成本可以由更大收入摊薄；若收入增长主要依赖少数融资需求大的模型公司，或新设备很快压低旧代租价，合同规模大仍可能伴随回收期延长。后续需要同时更新在用容量、客户现金回款、单位服务成本和资本承诺，不能仅以订单或token量替代这些观察。本页没有给出三家企业统一的2026年末盈利预测。
