# 光模块、交换机与网络互联

> 执笔：`/root/resume_b040`；制作日2026-10-30。有明确日期的技术演变覆盖至2026-01-06；NCCL动态说明于制作日核读，不据此声称掌握2026年全部出货情况。

## 概念定义

网络互联是让计算节点、存储和使用者交换数据的一整套硬件、协议与软件。光模块承担电信号与光信号之间的转换；交换机根据目的地址或交换规则把数据送到相应端口；网卡把服务器接入网络；光纤或铜缆承担实际传输。它们共同决定集群能否把许多处理器组织成可用的计算资源。

在AI集群中，这个对象的核心不是“网速越快越好”，而是通信能否在计算所需的时间内完成。数据并行训练要汇总各处理器算出的梯度；模型分布在多台机器时，中间结果也要跨设备移动。某个节点迟到可能让其他节点等待，因此平均带宽、延迟的尾部、故障后的恢复时间都有经济意义。NVIDIA的NCCL提供all-reduce、all-gather等集体通信操作，并按PCIe、NVLink及跨节点网络拓扑组织通信。[S-C-TECH-10-02](#S-C-TECH-10-02)

## 概念详解

### 从一条链路到整个集群

一条光链路通常包含发射端电路、光发射器、传输介质、接收器及接收端电路。模块规定速率、波长、距离、封装和电气接口，不能只凭同为“800G”就断定可互连。800 Gb/s表示每秒800吉比特的标称数据速率，换算为字节为100 GB/s；协议、编码和实际通信组织会影响应用最终得到的有效吞吐。

交换芯片的总带宽则是多个端口的合计能力。假设一台交换机有64个400 Gb/s端口，端口速率相加是25.6 Tb/s；若另一份材料把收发两个方向相加，数字会翻倍，而设备能力未变。这是口径演示，不对应特定产品。比较交换容量时，应同时保存端口数量、单端口速率和单向／双向计数方式。

交换机还需要足够的上行容量。假设接入层连接32台各400 Gb/s的服务器，总接入带宽为12.8 Tb/s，向上只有16条同速链路，即6.4 Tb/s。当所有服务器同时向其他接入层发送满速数据时，上行无法全部承载；这种2∶1收敛配置可以降低设备与线缆成本，却使跨接入层通信成为瓶颈。若多数流量留在本地或峰值错开，损失可能较小。节点数量相同的集群，拓扑不同，实际训练效率也会不同。

### 计算互联有不同层级

| 层级 | 主要任务 | 容易误读之处 |
|---|---|---|
| scale-up，紧密计算域内互联 | 让一组GPU频繁交换模型与中间数据，例如NVLink／NVSwitch | 专用域内带宽不能直接当作服务器对外网络带宽 |
| scale-out，跨服务器或机架 | 通过InfiniBand或以太网扩展集群 | 协议名字不足以决定性能，还取决于拓扑、网卡、拥塞控制和软件 |
| 存储与管理网络 | 读取训练数据、保存检查点、配置和监控设备 | 管理口数量与训练网络端口数不是同一需求 |

这些层级可以共享设施，也可以分网建设。增加GPU前应判断当前工作负载在哪个层级等待，否则升级了错误的一段链路，计算时间仍不会缩短。[S-C-TECH-10-02](#S-C-TECH-10-02)

### 带宽为什么不等于训练速度

本页用一个明确的假设模型说明瓶颈：若每步计算耗时80毫秒、通信耗时40毫秒，且完全不能重叠，总时间为120毫秒。通信带宽翻倍、其余不变且通信完全受带宽限制时，通信降到20毫秒，总时间100毫秒，速度只提高20%，而非翻倍。若原来通信已全部隐藏在计算期间，同样的带宽升级可能几乎不改变总时间。

实际通信还包含固定启动延迟、排队与同步。小消息可能受延迟限制；大消息更容易受持续带宽限制。通信库选择环、树等算法，也会改变数据通过哪条链路、分多少轮发送。NCCL的拓扑发现和算法选择正是在处理这些差异，并不构成所有任务均能达到硬件峰值的保证。[S-C-TECH-10-02](#S-C-TECH-10-02)

混合专家模型还把不同token分派给不同专家，流量可能不均匀。网络抖动或热点会使少数路径拖慢整体。NVIDIA于2026-01-06的技术文章特别强调低抖动对专家分派和推理吞吐的作用；这是厂商的设计解释，本页未把其对自身平台的相对性能宣称当作跨厂商独立测评。[S-C-TECH-10-04](#S-C-TECH-10-04)

### 可插拔模块、硅光与共封装光学

可插拔光模块位于设备端口，交换芯片先通过板上电连接把数据送到模块。它便于按距离和速率配置、替换；但高速电信号走过较长板级路径，会增加信号恢复、供电和散热要求。

共封装光学（CPO）把光引擎靠近交换芯片封装，缩短高速电通道。硅光是用硅基工艺集成光学功能的技术路线，CPO是集成和封装位置，二者不是同义词；硅光也可进入可插拔模块。CPO改变的是光电转换发生的位置，不会让光纤、连接器或激光器需求消失。其生产测试、光纤装配和维护方式亦随之变化。

2026年NVIDIA文章解释了预装配筛选光引擎、可拆光纤连接及自动化装配的作用，并给出SN6800的409.6 Tb/s、512个800 Gb/s端口配置。这是交换系统规格；不能把409.6 Tb/s算成单颗GPU可获得的带宽。厂商所述每1.6 Tb/s端口五倍功耗改善需要其比较基准，本页不外推为整个数据中心节电80%。[S-C-TECH-10-04](#S-C-TECH-10-04)

## 观测与数据口径

产业需求应从实际网络配置向器件数量推导：服务器网卡端口数、接入与汇聚层端口数、链路长度、铜／光选择和备用数量，分别决定需求。只用“GPU数量×固定模块数”会忽略机架内铜互联、交换层级及端口拆分变化。一条采用两端可插拔收发器的链路通常需要两个端点模块；若采用有源光缆或CPO，物料计量方式会不同，不能套用同一个倍数。

| 指标 | 有效的读取方式 |
|---|---|
| 光模块出货量与收入 | 按速率、距离和封装分组；收入变化还包含售价和产品组合 |
| 交换机端口与交换容量 | 区分ASIC、整机、端口拆分及收发计数口径 |
| 应用吞吐与通信耗时 | 固定模型、精度、节点数、消息大小和软件版本后比较 |
| 可靠性 | 区分单链路故障、短暂链路中断、整项作业失败与恢复时间 |
| 成本 | 同时看网络采购、功耗、维护及通信等待造成的GPU闲置 |

本页的成本判断为条件性分析：提高网络投入若能显著减少昂贵计算设备的等待，可能降低单位有效计算成本；如果工作负载本来不受通信限制，更高规格可能只是增加成本。没有实测作业效率与采购价，不能计算通用回收期。

## 本对象的历史与预期

IEEE于2024年4月回顾，以太网从2002年10GbE、2010年40／100GbE、2017年200／400GbE走到2024年800GbE。800GbE的重要工程特点之一，是复用100 Gb/s通道并通过八通道组织更高速接口，而非要求每条物理通道都达到800 Gb/s。这也支持一个端口按较低速率拆分配置。这里采用标准组织的技术说明，没有把标准通过日期当作全行业完成升级的日期。[S-C-TECH-10-01](#S-C-TECH-10-01)

2025-03-18，NVIDIA宣布Spectrum-X与Quantum-X光子交换机，当时预计后者于2025年稍后、前者于2026年可用。公告还明确把CPO与可插拔光模块生态并列，说明其当时并未宣称所有可插拔产品会立即退出。产品发布、量产供货和客户稳定运行是不同里程碑，公告只能支持前两者中的“发布及供货计划”。[S-C-TECH-10-03](#S-C-TECH-10-03)

2026-01-06的技术文章进一步说明光引擎与封装、装配和交换拓扑。其信息增加了对实现方式的理解，但本文未取得可核验的客户装机量、光模块替代比例和跨厂商故障数据，不能以技术规格验证2025年计划已全部兑现。[S-C-TECH-10-04](#S-C-TECH-10-04)

**本库条件推演，整理于2026-10-30：** 若集群规模和跨节点通信量继续增加，端口速率与交换层级的优化会共同影响网络价值量；若更多通信留在紧密计算域内，外部光模块数量未必与GPU数量同比增长。CPO若在装配良率、维护与整机成本上取得优势，价值可能向光引擎、封装和连接器转移。判断需观察实际采用拓扑与订单，而不能把厂商技术路线图直接当作供应商收入预测。
