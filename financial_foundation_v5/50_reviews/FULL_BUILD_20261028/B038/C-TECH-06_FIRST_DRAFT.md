# HBM与存储芯片

> 执笔：`/root/resume_b038`，GPT-6-Astra，medium；制作日2026-10-30。最近核读的有日期材料为Micron 2026财年10-K（签署2026-10-09，财年截至2026-09-03），仅抽读本文相关章节；并非三家厂商截至制作日的全量更新。

## 概念定义

存储芯片用于保存和读取数据，服务于计算过程中的工作内存以及断电后仍需保留的长期存储。HBM，即高带宽内存，是以多层DRAM芯片垂直堆叠、通过硅通孔TSV连接的内存架构，重点是在有限空间和能耗约束下提高与处理器交换数据的吞吐量。它属于DRAM，不是与DRAM平行的第三种基础存储介质。[S-C-TECH-06-01](#S-C-TECH-06-01)

本页讨论带宽、产能与产品周期。理解HBM的价值，需要同时看到计算系统怎样使用数据和制造商怎样把晶圆转为合格产品：算得更快的处理器可能等不到数据，而有大量普通存储产能的工厂也不能立即交付同等数量的合格HBM。

## 概念详解

### DRAM、NAND与HBM分别承担什么任务

DRAM提供高速、低延迟的数据读取，但断电丢失内容，通常用作运行时工作内存；NAND断电保留数据，常被组成固态硬盘SSD等存储产品，适合较大容量的数据保存。SSD还包括控制器、固件及可能使用的DRAM，不能把整块SSD的售价或吞吐量视作一颗NAND芯片的指标。[S-C-TECH-06-01](#S-C-TECH-06-01)

DDR、LPDDR、GDDR和HBM都是面向不同功耗、连接和应用要求的DRAM产品路线。HBM适合高数据吞吐的加速器，不意味着一般服务器内存、移动内存或NAND会全部被其替代。AI系统可以同时使用GPU旁的HBM、CPU的工作内存以及存储模型文件和数据集的SSD：每一层解决不同容量、带宽、延迟和成本问题。

这里的“存储容量”与工厂“产能”必须分开。前者是一个产品能放多少数据，常用GB；后者是期间能生产多少晶圆、合格芯片或比特。新闻中的“容量增加50%”，需要先确定说的是单个HBM堆栈还是工厂每月供给。

### 容量、带宽、延迟：三个不能合并的性能指标

容量回答能同时放入多少数据；带宽回答单位时间能搬运多少数据；延迟回答发出一次请求以后多久得到响应。大模型的权重、运行中间结果及缓存占用内存，放不下时需要改变精度、切分模型或在不同存储层之间搬运数据；这些选择会改变通信开销和服务质量。

**容量假设算例：**700亿个参数，若每个参数以16位即2字节保存，仅权重约需140 GB（十进制）。若每个参数平均用4位表示，理论原始权重为35 GB，但实际还需量化元数据、缓存、中间结果和运行空间。因此35 GB不是整套服务所需内存的完整估计，更不代表改变精度以后模型质量不变。

带宽的基础算式为：

\[
B_{pin}=W\times r/8.
\]

W为数据接口宽度（位），r为每引脚每秒传输的比特数，除以8将bit换成byte。若r以Gb/s表示，结果为GB/s。这里是接口理论吞吐；实际连续带宽还受访问模式、刷新、读写切换、控制器及软件影响。

JEDEC于2025年公布的HBM4规范说明给出2048位接口、最高8 Gb/s传输率和约2 TB/s带宽。按算式为2048 GB/s，即2.048 TB/s（十进制）；公开说明将其表述为2 TB/s。支持的配置包含4、8、12、16层DRAM，24或32 Gb单片密度；32 Gb乘16层再除8可得64 GB。规范允许的配置上限不是每个厂商当时已量产的产品。[S-C-TECH-06-02](#S-C-TECH-06-02)

### 为什么提升内存带宽可能比继续堆计算单元更有用

Williams、Waterman和Patterson的Roofline模型把计算吞吐上限与内存流量联系起来。简化表达为：

\[
P\leq\min(P_{compute},B_{sustained}\times I).
\]

P为每秒浮点运算量，计算上限需对应同一数值精度；B为系统可持续内存带宽（byte/s），I为每个从该内存层传输的字节对应的运算次数（FLOP/byte）。这里应计缓存处理后真正到内存的流量，而不是机械累加程序中所有变量访问；B也不应直接使用芯片引脚宣传峰值。[S-C-TECH-06-03](#S-C-TECH-06-03)

**假设算例：**一个计算内核的计算峰值100 TFLOP/s，可持续带宽1 TB/s，I为20 FLOP/byte，则带宽项为20 TFLOP/s，上限先受内存限制。把带宽提高到2 TB/s，理论上限提高至40 TFLOP/s；若I提高到100，则原带宽也足以达到100 TFLOP/s的计算上限。这个模型给出瓶颈边界，未计通信同步等额外损耗，不预测整项AI任务必定按比例加速。

由此可以解释HBM需求和软件优化的关系：减少重复读写、提高数据复用，会改变所需带宽；扩大模型、上下文或并行服务量又可能增加内存压力。不能仅用GPU峰值算力增长率，推导HBM每一代必须以相同比例增长。

### 从晶圆到合格HBM：供给由多个环节共同决定

HBM先需要合格的DRAM裸片，再经过薄化、TSV、堆叠、连接、测试等步骤形成堆栈，最后与处理器及其封装系统配合使用。堆叠层数上升并不只是多放几片芯片：厚度、翘曲、散热、连接可靠性和测试都要满足要求。SK hynix于2024-09-26说明，其36 GB、12层HBM3E保持此前8层产品的总厚度，为此将单片DRAM薄化约40%，并使用其封装工艺控制结构及散热问题。[S-C-TECH-06-04](#S-C-TECH-06-04)

一个概念性供给核算可以分成三个数量：晶圆提供的合格DRAM比特、堆叠测试后可售的HBM比特、最终通过客户系统认证并可交付的比特。某一环扩产，只有其他环节也能承接，才会增加最终供给。不能把宣布增加晶圆投片直接等同于同月HBM收入增长，也不能把先进封装总产能都归作HBM堆叠产能。

Micron管理层在2025-03-20表示，生产相同比特数的HBM3E相对D5需要约三倍硅用量，并预计该比值随HBM4、HBM4E进一步提高。这是该公司当时的产品和工艺口径，不能当成每家厂商、每代产品的固定倍数，更不是“三倍硅就必然三倍成本”。[S-C-TECH-06-05](#S-C-TECH-06-05) 它的经济含义是：在可调配的先进DRAM资源有限时，转向HBM可能减少本可生产的普通DRAM比特数；利润仍取决于售价、良率、封装测试及客户交付。

新增厂房和设备、工艺迁移、产品认证各有时间表。样品用于验证，认证通过允许进入特定平台供货，量产意味着生产规模爬升；它们不代表同一里程碑。一家厂商在一个客户产品上成功，也不能自动证明其所有配置已获所有客户接受。

## 价格、供给周期与观测口径

普通DRAM、NAND及HBM存在部分共同需求和资本资源，但不能用一个价格代表整个市场。HBM还受到客户平台节奏、产品代际和认证约束。短缺可以表现为某代、某堆叠高度或某客户认证配置不足，同时其他产品仍有库存。

供给反应也具有方向性：需求强时，高利润产品吸引资源和新增投资；这些投资经过建设和爬坡以后才形成供给。若届时客户减少需求或产品更替，库存和价格可能承压。Micron 2026年报的风险披露明确讨论：HBM需求走弱后，供应商若转回普通DRAM，可能显著增加普通DRAM供给。这里是公司披露的条件风险，并不是本文断言该转换已经发生。[S-C-TECH-06-01](#S-C-TECH-06-01)

| 指标 | 应保留的口径 | 研究含义 |
|---|---|---|
| 单片／堆栈容量 | Gb还是GB、层数、可用容量 | 分清每片密度与完整产品容量 |
| 带宽 | 单引脚、单堆栈或整颗加速器；峰值或实测 | 避免把位速率当字节吞吐或重复计算 |
| 供给 | 晶圆投片、合格比特、堆栈数、出货量 | 找到实际限制的生产环节 |
| 良率 | 裸片、堆叠、最终测试分别说明 | 不把一种良率直接外推全流程 |
| 价格与收入 | 现货或合同；每比特、每堆栈；产品组合 | 收入增长可能来自数量、价格及组合变化 |
| 订单与认证 | 哪一客户、平台、配置、交付期间 | “售罄”对应公司计划供给，不是全行业需求已满足 |
| 投资 | 厂房、设备、封装、测试；投产和爬坡日期 | 开支支付不等于可售产品立即增加 |

HBM收入也不能用云内存部门总收入代替，因为该部门可能同时销售DDR、LPDDR和其他产品。厂商未披露单独HBM收入或良率时，应保留缺口，不能按一个市场份额传闻拆分财务报表。

## 本对象的历史与带归属的预期

**从堆叠内存到AI关键部件。**SK hynix在2024年公告中回顾其2013年推出首代HBM，此后经过HBM2、HBM2E、HBM3到HBM3E。这个回顾来自厂商自身，对“世界第一”等宣传不作独立行业史裁定；可以确认的是产品持续沿容量、带宽和封装能力演进，而非只在生成式AI出现后才诞生。[S-C-TECH-06-04](#S-C-TECH-06-04)

**2024年：8层量产与12层升级。**Micron于2024-02-26宣布24 GB、8层HBM3E量产，称产品带宽超过1.2 TB/s，拟用于第二自然季度出货的NVIDIA H200；同一公告把36 GB、12层产品列为随后送样。到9月，SK hynix宣布36 GB、12层HBM3E量产，计划年内向客户供货。两份材料分别记录不同厂商的产品阶段，不应拼成同一家公司从样品到收入的时间序列。[S-C-TECH-06-06](#S-C-TECH-06-06)、[S-C-TECH-06-04](#S-C-TECH-06-04)

**2025年3月的信息集。**Micron管理层报告2025财年第二季度HBM收入超过10亿美元，环比增长超过50%；预计自然年2025全球HBM可服务市场超过350亿美元，并称其当年计划产出已售罄。前者是公司季度收入，后者是管理层行业市场估计和供给承诺表述，不能将350亿美元当作已经实现的销售。管理层同时判断HBM4于自然年2026量产爬升。其当时还报告数据中心NAND受短期客户库存影响而需求放缓，说明HBM强劲与其他存储产品调整可以共存。[S-C-TECH-06-05](#S-C-TECH-06-05)

**2025年4月：接口标准扩展。**JEDEC发布HBM4标准，扩大接口和通道数，同时支持更高堆栈容量。标准统一接口语言，使供应链能够共同设计，但并不承诺所有产品在发布日期即以规范上限量产。本文读到的是JEDEC自行发布的公告，而非标准全文。[S-C-TECH-06-02](#S-C-TECH-06-02)

**2026年后来结果及下一代预期。**Micron截至2026-09-03财年的10-K记录：12层HBM3E占其当年HBM出货多数，36 GB、12层HBM4已开始量产，48 GB、16层HBM4已向多个重要客户送样；公司预计HBM4E在自然年2027量产爬升。这为其2025年的HBM4计划补上后来结果，但没有核实2025年全球350亿美元市场预测的最终实现值。更不能把2027目标写成已交付产品。[S-C-TECH-06-01](#S-C-TECH-06-01)

**本库条件推演，2026-10-30整理：**若加速器平台需求保持且更高层数产品良率改善，合格堆栈供给可增加；若处理器封装、客户认证或站点电力成为瓶颈，内存厂扩产未必立即转成终端算力。反向情形下，HBM需求和普通DRAM需求若同时降温，产品转换可能放大普通DRAM价格压力。需用分代订单、实际出货、库存与价格验证，不凭“AI增长”直接否定存储周期。
