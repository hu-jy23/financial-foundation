# 正文与整合审阅清单 v5

更新：2026-10-25。审阅者先通读，再按下列项目定位问题；不要把这些项目变成正文的强制字段。

1. **解释是否成立**：定义明确；概念详解说明构成与含义；详细逻辑交代主体、作用过程和结果。能否用自己的话复述？若只能复述限制条件，须重写解释。
2. **语言是否明确**：句子通顺，主语和指代清楚，术语有必要说明，段落衔接自然。删除空泛的“影响”“承接”“重定价”等表述，或补出其具体对象和过程。
3. **深度是否合适**：充分解释重要难点；基础概念不因模板而扩写入门教程。条件与反例放在相应判断旁，避免重复堆积。
4. **逻辑与历史是否相连**：每条关系逻辑绑定节点，并各自附时间线和预期。历史补充具体情境，不重复整段抽象机制。
5. **证据是否支持**：核读关键原文及数据口径；重要数字按对象选择，缺失状态具体。区分事实、模型、作者解释及本库推演，保留定性条件推演。
6. **时间是否准确**：分清事件发生、材料公开、后补记录及证据截止；后来结果不进入当时的信息集。
7. **版本是否真实**：逐篇记录采用与编辑范围。未经重写的正文标为保留，未读资料保持未读；模型、档位与署名有依据。
8. **结构是否一致**：检查 ID、文件路径、锚点、来源登记和目录状态；来源事实有修正时同步检查相关事件与引用。

自动校验覆盖结构和链接；解释质量与证据是否充分由人工式通读判断。最终记录应指出具体缺口，不以“全部通过”暗示资料齐全或市场信息实时。


## Event 与 Source 的额外审阅

- 内容单元是否完整？是否因每页或每图新增了零散条目？是否存在为了减少文件而硬并无关材料？
- Event 是否保留事件与分析本身？关键数字、图表、评论是否仍只在来源链接或关系页？
- 清楚的原页是否被不必要地压缩或复述？图例、坐标、单位及作者批注是否保留？
- Source 是否有原始出处、已读范围、进入正文的位置及有价值的阅读笔记和延伸问题？缺少延伸问题时无需凑数。
- 原文与编辑说明、历史观点与后来结果是否可区分？路径、图片和旧 ID 是否完整？

## 目录使用与内容归属

- 是否沿用已确认ID、名称和范围，避免因研究中遇到术语而扩充目录？[选取原则](NODE_SELECTION_GUIDE.md)用于理解取舍，当前逐项结果见正式目录。
- 正文解释是否充分，又是否把普通指标、一般常识和行业化的简单因果误建成节点？
- node_ids是否只含入选对象，related_mechanism_ids是否只含入选关系？
- 待写节点是否链接目录锚点，完成后是否同步正文路径、状态和逻辑组？旧ID是否仍可追溯？
- 用户明确限定的回补、迁移和拆分是否保持；历史细节见[项目记忆](CONVERSATION_MEMORY.md)。
