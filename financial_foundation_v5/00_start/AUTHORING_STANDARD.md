# 金融认知 Map：批量制作标准 v5

规范定稿：2026-10-25；制作进度更新：2026-10-27。适用于人工、Codex 和 subagent；成品位于 `10_concepts/`、`20_mechanisms/`。用户现有的老师宏观 PPT 是重要起点；教材、研究论文、深度博客和历史分析由研究 agent 主动搜集，逐步形成专业认知材料库。四份机制／概念样例原先使用公开资料；现已逐页读取用户提供的 2025 年 3 月 30 日课件，并已在本版课程材料集中按完整论述接入原页。现行文件职责与状态说明见[制作入口](README.md)。

## 1. 交付对象与写作单位

- **概念／对象 node**：保存这个对象的定义、详解、必要的辨析、观测口径和历史。可以保留丰富内容及关系入口；百来行乃至更长都可以，以解释清楚为准。
- **关系／机制条目**：作为本库可独立维护的关系节点，保存已有对象间的关联。下文的edge／hyperedge指它所表达的关系及多对象逻辑，不另增加一套节点目录。先用“概念定义＋概念详解”讲清关系，再以每组相关节点的一条完整逻辑为单位，连续写出逻辑、历史和预期。
- **事件与分析材料**：独立积累事件、过程、预期、评论、反思及图表；保留有价值的完整材料与作者思路，允许原页嵌入。按内容单元组织，图表及零散片段可直接附到已有条目。组织细则见 [Event 与 Source 指南](EVENT_SOURCE_GUIDE.md)。
- **Source／材料工作区**：保留出处、原材料、阅读摘记、论证层次与延伸问题；已入库的事件与分析在相应正文中完整承载。主动搜集教材、课程、专题研究与深度分析，积累逐页／逐章阅读记录；来源登记是入口。

对象与关系制作只从本版正式目录选择。163个对象和71个关系／机制已确认为初步建图节点；正文待制作状态不影响入选状态。旧ID登记用于追溯，正文使用普通变量无需新增节点。

**已确认范围（v5）**：对象163项、关系71项，共234个节点。后续制作直接使用正式目录中的ID和名称。106项未入选关系、186项未入选对象及2项通用研究规则均不进入制作队列。需要调整节点范围时提出独立变更，不在制作过程中顺带新增、回补或拆分。

选取中的平凡性判断、对象与关系的归属、拆分及命名取舍见[节点选取与命名原则](NODE_SELECTION_GUIDE.md)。材料出现新术语，先决定怎样解释和归属，不自动产生新节点。

## 2. 概念／对象文档

基本结构：概念 → 概念定义 → 概念详解 → 必要的相近概念与边界 → 观测与数据口径 → 本对象历史 → 涉及的关系 → 来源。可以合并内容很少的节，不按字数凑章节。

定义说清对象是什么；详解讲清其内部含义、组成和必要公式；历史记录对象自身的制度、测量或状态变化。关系的成套传导逻辑写在 edge，概念页只留有意义的入口。

保留概念特有的易错点。例如：TIPS 收益率含期限、流动性等成分；期限溢价依赖模型和数据版本。通用的时点、来源、写作规则统一放在本标准。

### 正文的解释职责

“概念定义”“概念详解”和“详细逻辑”承担类似教材定义与论证段落的职责。读完后，应能明确说出对象是什么、关键量代表什么、主体通过什么过程产生结果。先建立正面的解释，再把必要条件与限制接到对应判断上。“不能保证……还需……”可以澄清边界，但连续罗列限制无法完成解释。

概念详解按对象组织：解释组成、经济含义及必要口径；使用公式时说明变量、单位、期限和假设。基础概念可利用目标读者已有知识，保留足够的衔接即可，不强制从生活例子或长篇入门过程讲起。agent 的先验知识不替代本文应有的定义和明确表述。

详细逻辑按实际因果展开：什么变化，谁受到影响，约束、收益或风险如何变化，主体如何回应，结果为何随之改变。无需机械套用这串问题，但不能用节点名串联、箭头或“影响定价”等笼统词代替中间过程。句子主语和指代明确；一段围绕一个解释任务，术语在首次需要时说明。条件复杂时拆成清楚的分支，保留真正影响结论的边界。

篇幅与教学深度由内容决定。基础概念可以简洁，复杂机制需要充分展开；两者都以连贯、准确、可理解为标准，不设统一长短，也不把某篇样例的开篇方式作为通用模板。

## 3. 关系／机制文档：必须遵守的结构

标题使用正式目录的已确认名称，沿用稳定ID。命名先确定机制核心和研究范围：已有清楚的机制名可直接使用，例如“金融加速器”“基差交易”；体现实际反馈、分解、比较或跨对象联系的“与”可以保留，例如“主权信用与银行资产负债表反馈”。

避免机械删除“与”，也避免把所有参与对象、条件和后果都拼进标题。改名须保持关键量及其含义：通胀预期、ETF份额变化、资产减值等不能在压缩时换成更宽泛或不同的量。名称质量、内容价值和是否独立入库分别判断；一次改名不自动改变选取结果。本版已吸收36项原名恢复。

1. **概念定义**：一个完整段落，清楚说明关系的含义。
2. **概念详解**：充分解释关系如何成立、讨论范围与必要背景。篇幅不限，但避免提前简略复述后面每条核心逻辑。
3. **核心逻辑 1、2……**：每条绑定单个节点或节点组，按下列顺序展开。
4. **其他相关逻辑 1、2……**：补充路径、制约条件和竞争性解释，采用相同顺序。按内容需要设置，不必凑齐。
5. **来源与待补问题**：精简入口；问题尽量附在对应逻辑下，便于定向研究。

每条逻辑包含：

> **关联节点／节点组**（使用稳定 ID 与可点击链接）  
> **时间段**（区分机制适用时期和本次已覆盖的证据区间）  
> **详细逻辑**（写清各节点的作用、共同作用条件、方向可能变化的原因）  
> **该逻辑的时间线**（明确本次资料截止；围绕该时点近一至两年的变化，并保留理解机制所需的重要历史）  
> **该逻辑的预期**（谁、截至何时、对什么、哪个期限、依赖哪些条件、什么新观察会改变判断）

一条逻辑可包含多个节点，也可从单一节点在整个关系中的作用展开。不同逻辑组可以共享节点。节点名单只使用本版入选对象；定义、指标和背景变量按正文需要解释，可另列“论证中的变量与术语”，不当作隐式节点。组内详细论证承载 hyperedge 的含义；一个参与对象名单无法替代它。

时间线与预期必须留在所属逻辑下面。不得在文末用一个总的“历史演变”或“预期表示”小节包办所有逻辑。需要共用一个事件时，引用同一事件记录，各自解释其含义。

## 4. 两个结构微例

以下只示范组织方法，属于待填证据的写法示意，不是已验证历史结论。

**黄金的机会成本机制／核心逻辑 1**  
关联节点：（黄金，实际利率）。详细解释同期限真实回报如何改变投资者持有黄金的机会成本，并说明选用哪个实际利率口径；紧接着写这条逻辑的具体事件、当时判断和带时间的预期。

**国债供给的定价机制／核心逻辑 1**  
关联节点：（财政赤字与初级赤字，财政部一般账户TGA，融资流动性，期限溢价）。发行期限和私人久期承接作为论证变量。解释融资额如何经发行期限和央行持仓变为市场需要承接的久期，再解释承接意愿如何影响定价；紧接着记录再融资公告及当时发行预期，再写后续供给和吸收能力的条件性预期。

## 5. 对象／关系页的历史与预期记录方法

以下信息要点用于对象／关系页的历史与预期，也可辅助阅读事件；它们不规定 Event 正文的章节：

> **截至时间｜当时状态｜谁对什么、哪个期限有何预期｜新增证据｜判断变化｜后续结果｜来源**

用自然段、条目或表格承载实际内容，不要求每条逐字段填写。时间线记录这条逻辑相关的事件、状态与判断怎样随时间变化；方向和强弱可以简要表达，复杂情境则充分说明。已有详细逻辑无需反复展开；具体事件中的背景、指标口径与传导变化仍应讲清，例如从政策利率转到十年期国债收益率时，要交代这里为何采用该量及其含义。表达形式与篇幅服从内容需要。

若后续结果来自较晚材料，明确标出其日期；截至时间只约束当时状态与当时预期，后续结果不回填到当时信息集。

每项预期说明出处：受访者／机构展望、市场价格隐含量，或基于当时状态作出的本库条件性推演。定性推演是正文的重要内容，可以充分讨论事情如何演变、依赖什么条件以及相关对象可能怎样变化，无需强配数字。标明信息边界与整理时间；自己的推演与当时专业判断相符时附上支持材料，保留各自归属和分歧。

重要数字依据对象或该条逻辑本身选择：它是否反映当时值得关注的事实状态、专业判断或预期？后续相关事件出现时，对照它能否理解事实走势、预期变化及其偏差？数字未变也可能有意义。记录所有由这段论证确认为关键的量；选择范围不预设下游 agent 的任务、策略或数据需求。百分比保留原来源的含义，不因其形式就重定义为事件概率或图的边权。

对已确定的重要数字，building agent 必须核读材料，并主动检索、必要时深入研究来补齐。随数字交代主体、日期、对象、单位、期限及比较基准；重要性与含义可以自然写入段落，不新增强制字段。保留实际值、专业预期、模型估算和本库推演的归属，单一观点不自动代表市场共识。

缺失须具体说明：哪个量没有数字、已查什么及为何仍缺失。区分“尚未搜集／提取”“已查来源未披露”“原始版本或数据未取得”“现有口径无法对应该量”；只写“待补研究”不足以交代状态。搜索不足时如实标明未完成，不能声称资料不存在；后续阅读者应能识别未知项，不能依据自身先验补造历史数字。

时间线侧重变化、预期侧重保存当时判断及关键数字，是内容重心。两处都可保留有用的数字与解释；无需强行拆分定性、定量，也不要求将每个历史时点的预期搬到文末。

关系页可写：满足某条件时哪些节点可能怎样变化、看什么观察来更新判断、适用期限和不确定性。这是关系知识。交易阈值、买卖动作、仓位、候选 alpha 与回测另由使用 map 的研究任务处理。

## 6. 来源与研究

材料搜集是建图的基础工作。用户材料提供初始框架和问题意识，研究 agent 同时主动建立外部材料库：基础教材／课程补齐概念，专题研究补齐机制，深度博客与机构文章补齐专业分析的隐含背景，历史材料与调查补齐当时判断和预期。第一批来源与选用理由见[资料搜集与阅读方案](../40_sources/ACQUISITION_SHORTLIST.md)。

以机制问题组织搜集。例如“财政融资如何改变长债定价”，同时寻找制度说明、条件性模型、关键历史案例和竞争解释。每组材料需说明各自贡献，避免同一观点的转载被当成多个独立证据。教材按章节读取；博客按具体文章及其前后更新读取。

检索先定位作者／出版社／大学／原发布机构，再核读目录、正文或章节；逐项记录链接、版本与日期、开放／付费状态、实际阅读范围。仅核目录的书登记为候选，不可写成已经吸收的知识。全文获取按合法可访问范围进行，未读部分明确保留。

制度、数据和事件事实核对一手来源；深度博客、机构评论保留完整论证、隐含前提及专业预期，标明作者与发布日期。观点归属于作者或受访群体。对有争议的机制补充有实质差异的解释，并说明各自需要什么证据。

每条重要判断能追溯到来源、页码／章节／表格。区分：定义／制度、条件性理论、经验观察、作者解释、本库推演。引用研究时保留论证所需条件，不能把相关性写成确定因果。

事件至少分清事件发生时间、材料公开时间，以及后来补录时间。日期粒度不足以判断是否赶上具体交易窗口时，明确说明未取得精确时刻。模型值保存估计方法和版本；修订值不能冒充当时可见值。

资料缺口转为具体问题。例如：“在 2025 年某次再融资公告前，一级交易商预期了哪些期限的发行规模？公告偏离了哪里？”研究任务应指定节点组、截止日期、要回答的问题和期望交付证据。不得把未经核实的示例事件直接写进历史。

Event 与 Source 的正文归属、跨页切分、图表嵌入和后续维护按[专门指南](EVENT_SOURCE_GUIDE.md)执行。材料入库先保持完整，再按实际需要建立对象和关系连接；课程中的每张图、每一页不自动成为新条目。

## 7. 简单元数据与链接

文档使用 YAML：`id`、`type`、`title`、`status`、`updated`；概念／关系再加 `evidence_as_of`（资料覆盖截止，不等于实时行情）和 `source_ids`。样例另标 `draft_author` 与 `reviewed_by`，正文标题后显示执笔与审阅归属。需要的其他字段再添加。

关系中各逻辑用稳定标题锚点或 HTML anchor（如 `logic-1`）；关联节点在该条正文列出；目录中的node_ids和logic_groups由最终正文同步核对，不能作为另一份独立推定的参与名单。关联对象只从concepts选择，相关关系单列为related_mechanism_ids。Markdown 是内容主载体，本轮不引入图数据库或运行时分层系统。

模板标为template，复制后按真实进度填写draft或审阅状态。新建独立Source笔记也使用最小元数据；已有合并来源登记可以继续用内部来源ID。正文状态、目录状态、日期和链接的口径见[制作入口](README.md)。

## 8. 制作与审阅

任务可以由主agent执行；采用subagent分工时，主 agent 先提供本标准、一个相关成品或以上微例、正式目录和明确任务。每个 subagent 只负责指定文件，优先共享文件路径；汇报仅含文件位置、主要缺口及需审阅之处，避免粘贴整份文档占用对话 context。

执行顺序：读现行入口、标准和样例 → 对齐已确认 ID → 设计少量针对性问题 → 搜集并筛选成组材料 → 逐篇／逐章阅读与记录来源 → 写文档及事件记录 → 自查 → 主 agent 审阅 → 修正、同步索引与引用后合并。采用分工时优先整组逻辑分派，避免把同一逻辑的历史、理论、预期分给互不沟通的任务。

主 agent 必须逐篇读完本批拟合并的正文，检查：标题范围、节点连接是否具体、论证是否充分、逻辑与历史预期是否相邻、具体情境是否解释清楚、重要数字及其缺失状态是否交代、定性推演的归属是否明确、当时与后来信息是否分清、关键来源是否支持相应判断、链接／ID 是否可解析。自动检查只负责结构和链接，内容判断由审阅完成。

每次分派保存实际任务文本、输入文件版本、负责路径及完成状态。模型和 reasoning effort 在已明确指定或有运行记录时如实记录；无法确认则注明未记录，不从 agent 名称推断。Astra medium 是2026-10-23两篇对照重写的实际配置，不自动成为所有后续任务的强制配置。执笔、后续编辑与审阅分别署名。

合并前按[审阅清单](REVIEW_CHECKLIST.md)检查解释功能、句子和证据。来源真实、格式齐全或模型较强，都不足以直接通过正文审阅。对每篇独立决定采用、局部修订或重写；某篇不可读的结论不外推到其他篇。更新标准后，应列明哪些正文已按新标准处理、哪些保留、哪些仍待处理；生成 patch 或升级版本号本身不等于所有正文已经重写。
