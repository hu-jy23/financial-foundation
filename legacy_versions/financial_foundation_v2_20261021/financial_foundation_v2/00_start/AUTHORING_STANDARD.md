# 金融认知 Map：批量制作标准 v2

日期：2026-10-21。适用于人工、Codex 和 subagent；四份成品位于 `10_concepts/`、`20_mechanisms/`。本轮未收到用户的宏观 PPT、书籍或博客原文，样例采用公开资料。

## 1. 交付对象与写作单位

- **概念／对象 node**：保存这个对象的定义、详解、必要的辨析、观测口径和历史。可以保留丰富内容及关系入口；百来行乃至更长都可以，以解释清楚为准。
- **关系／机制 edge**：在已有概念节点上构建关联。先用“概念定义＋概念详解”讲清关系，再以每组相关节点的一条完整逻辑为单位，连续写出逻辑、历史和预期。
- **事件／观察**：记录可复用的事实、原话、数据或分析观点，并附来源 hook；关系页说明这份证据怎样改变该条逻辑。
- **材料工作区**：保留来源、阅读摘记、论证层次与待研究问题。来源登记是入口，获得 PPT／书籍／博客后再积累逐页／逐章阅读记录。

候选清单是待制作目录。候选 ID 已存在不表示对应 Markdown 已写完。引用候选节点时链接到清单锚点并注明“待制作”；已有文档则链接到文件。

## 2. 概念／对象文档

基本结构：概念 → 概念定义 → 概念详解 → 必要的相近概念与边界 → 观测与数据口径 → 本对象历史 → 涉及的关系 → 来源。可以合并内容很少的节，不按字数凑章节。

定义说清对象是什么；详解讲清其内部含义、组成和必要公式；历史记录对象自身的制度、测量或状态变化。关系的成套传导逻辑写在 edge，概念页只留有意义的入口。

保留概念特有的易错点。例如：TIPS 收益率含期限、流动性等成分；期限溢价依赖模型和数据版本。通用的时点、来源、写作规则统一放在本标准。

## 3. 关系／机制文档：必须遵守的结构

标题直接命名关系。样例标题为“黄金的机会成本机制”“国债供给的定价机制”。沿用稳定 ID，标题改进无需改 ID。

1. **概念定义**：一个完整段落，清楚说明关系的含义。
2. **概念详解**：充分解释关系如何成立、讨论范围与必要背景。篇幅不限，但避免提前简略复述后面每条核心逻辑。
3. **核心逻辑 1、2……**：每条绑定单个节点或节点组，按下列顺序展开。
4. **其他相关逻辑 1、2……**：补充路径、制约条件和竞争性解释，采用相同顺序。按内容需要设置，不必凑齐。
5. **来源与待补问题**：精简入口；问题尽量附在对应逻辑下，便于定向研究。

每条逻辑包含：

> **关联节点／节点组**（使用稳定 ID 与可点击链接）  
> **时间段**（区分机制适用时期和本次已覆盖的证据区间）  
> **详细逻辑**（写清各节点的作用、共同作用条件、方向可能变化的原因）  
> **该逻辑的时间线**（近期一至两年优先，必要时补重要历史）  
> **该逻辑的预期**（谁、截至何时、对什么、哪个期限、依赖哪些条件、什么新观察会改变判断）

一条逻辑可包含多个节点，也可从单一节点在整个关系中的作用展开。不同逻辑组可以共享节点。组内详细论证承载 hyperedge 的含义；一个参与对象名单无法替代它。

时间线与预期必须留在所属逻辑下面。不得在文末用一个总的“历史演变”或“预期表示”小节包办所有逻辑。需要共用一个事件时，引用同一事件记录，各自解释其含义。

## 4. 两个结构微例

以下只示范组织方法，属于待填证据的写法示意，不是已验证历史结论。

**黄金的机会成本机制／核心逻辑 1**  
关联节点：（黄金，实际利率）。详细解释同期限真实回报如何改变投资者持有黄金的机会成本，并说明选用哪个实际利率口径；紧接着写这条逻辑的具体事件、当时判断和带时间的预期。

**国债供给的定价机制／核心逻辑 1**  
关联节点：（财政融资，国债期限结构，私人部门久期承接，期限溢价）。解释融资额如何经发行期限和央行持仓变为市场需要承接的久期，再解释承接意愿如何影响定价；紧接着记录退款公告及当时发行预期，再写后续供给和吸收能力的条件性预期。

## 5. 历史与预期的记录方法

统一语义顺序：

> **截至时间｜当时状态｜谁对什么、哪个期限有何预期｜新增证据｜判断变化｜后续结果｜来源**

可用表格，或按这个顺序逐字段写段落，保持可读性。若后续结果来自较晚材料，明确标出其日期；截至时间只约束当时状态与当时预期，后续结果不回填到当时信息集。

每项预期需要说明出处：受访者／机构预测、市场价格隐含量，或本库的条件性推演。保留意见分歧；单一作者观点不能自动升级为市场共识。缺少事前材料就写“未取得”，不靠事后解释补造。

关系页可写：满足某条件时哪些节点可能怎样变化、看什么观察来更新判断、适用期限和不确定性。这是关系知识。交易阈值、买卖动作、仓位、候选 alpha 与回测另由使用 map 的研究任务处理。

## 6. 来源与研究

优先使用用户材料，其次按缺口检索。制度、数据和事件事实核对一手来源；深度博客、机构评论用来保留解释及专业预期，标明作者与发布日期。不要把来源偏好变成机械排除分析文章的规则。

每条重要判断能追溯到来源、页码／章节／表格。区分：定义／制度、条件性理论、经验观察、作者解释、本库推演。引用研究时保留论证所需条件，不能把相关性写成确定因果。

事件至少分清事件发生时间、材料公开时间，以及后来补录时间。日期粒度不足以判断是否赶上具体交易窗口时，明确说明未取得精确时刻。模型值保存估计方法和版本；修订值不能冒充当时可见值。

资料缺口转为具体问题。例如：“在 2025 年某次退款公告前，一级交易商预期了哪些期限的发行规模？公告偏离了哪里？”研究任务应指定节点组、截止日期、要回答的问题和期望交付证据。不得把未经核实的示例事件直接写进历史。

## 7. 简单元数据与链接

文档使用 YAML：`id`、`type`、`title`、`status`、`updated`；概念／关系再加 `evidence_as_of`（资料覆盖截止，不等于实时行情）和 `source_ids`。需要的其他字段再添加。

关系中各逻辑用稳定标题锚点或 HTML anchor（如 `logic-1`）；关联节点在该条正文列出即可，无需重复维护第二份参与名单。Markdown 是内容主载体，本轮不引入图数据库或运行时分层系统。

## 8. Subagent 制作与审阅

主 agent 先提供本标准、一个相关成品或以上微例、候选清单和明确任务。每个 subagent 只负责指定文件，优先共享文件路径；汇报仅含文件位置、主要缺口及需审阅之处，避免粘贴整份文档占用对话 context。

执行顺序：读标准和样例 → 对齐候选 ID → 设计少量针对性问题 → 研究与记录来源 → 写文档及事件记录 → 自查 → 主 agent 审阅 → 修正与合并。优先整组逻辑分派，避免把同一逻辑的历史、理论、预期分给互不沟通的任务。

主 agent 必须读完四份样例，检查：标题范围、节点连接是否具体、论证是否充分、逻辑与历史预期是否相邻、当时与后来信息是否分清、关键来源是否支持相应判断、链接／ID 是否可解析。自动检查只负责结构和链接，内容判断由审阅完成。

## 9. 本轮交付边界

交付广覆盖候选目录、可复制模板、批量任务说明、四份完整样例、支撑事件和来源记录。四份样例中的文档完整性指论证结构和已覆盖材料完整，不代表全体候选已经入库，也不代表已获得截至制作日的实时预期。
